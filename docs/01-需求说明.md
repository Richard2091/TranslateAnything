# 01 · 需求说明

## 一句话

按下全局快捷键，像 PixPin 截图一样框选屏幕上的一块区域，该区域内的文字被自动识别并翻译，译文以一个可拖动、可缩放的浮窗"滤镜"覆盖显示在原区域上；浮窗移动或改变大小后，自动对新覆盖的区域重新识别翻译。

## 核心交互流程（2026-11-16 用户改定为沉浸式实时翻译）

1. **触发**：全局快捷键（默认 `Alt+T`，可配置）在任意应用上按下。
2. **框选**：屏幕**不置灰**，只画选区边框；按住左键拖出矩形，松开即确认；`Esc` 或右键取消。
3. **沉浸式覆盖**：确认后选区变成一个只有边框的"翻译框"。框内文字按段落识别，在**原文所在位置**用取样的背景色盖住原文、以取样的文字色显示译文，字号自动适配，看起来像软件本身就是这种语言；不另开窗口显示译文。
4. **实时翻译**：翻译框持续检测框内画面，内容一变就重新识别，不是一次性翻译。
5. **跟随滚动/缩放**：框内内容滚动或缩放时，译文随之平移/重排；已翻译过的段落直接复用缓存，只有新进入框内（上下左右）的文字才请求翻译。
6. **框内鼠标操作**：默认「鼠标穿透」，在框内正文点击或滚动可操作下方应用。切换到「框内拖动」后，可按住正文区域移动翻译框，框内点击和滚轮由翻译框接收。两种模式都可从边缘缩放、用工具条手柄移动。移入框内时右上角出现工具条，可切换当前框的鼠标操作、切换原文/译文、暂停/继续或关闭。设置里的「框内鼠标操作」仅决定之后新建框的默认模式。
7. **多翻译框**：允许同时存在多个翻译框（再次按快捷键新开一个）。

同一个 Windows 登录会话只允许一个随译主进程。程序已在托盘常驻时，再启动安装版或便携版，新进程会自动退出。

## 明确不做

- 图像编辑、标注、贴图等截图软件功能。
- 历史记录/生词本（以后再说）。
- macOS / Linux 支持（第一版只做 Windows，发布 x64 与 ARM64 两个架构；其他平台的适配方案见 `02-技术方案.md`「多平台打包与发布」）。

## 验收标准（第一版）

- 在浏览器、PDF 阅读器、任意桌面应用上，快捷键 → 框选英文段落 → 2 秒内浮窗显示中文译文。
- 框选网页正文后滚动页面，译文跟随滚动，新出现的段落在 1 秒左右内被翻译。
- 拖动或缩放翻译框后，自动对新区域重新识别翻译。
- 默认「鼠标穿透」时，在框内正文点击按钮、滚动可滚动区域，下方应用照常响应，译文跟随画面。切到「框内拖动」后，正文左键拖动只移动翻译框，点击和滚轮不传给下方应用。下方画面未动时，译文也不应出现由滚轮触发的假位移。
- 修改配置文件中的 base URL / key / 模型后重启生效（有设置界面则免重启）。
- OCR 失败、API 失败时浮窗内有可读的错误提示，不崩溃。

### 启动行为手动验收（Windows）

1. 在测试账号打开「设置 → 常规」。确认开机自启动默认关闭；开启后重新打开设置，仍应显示开启。注销并重新登录，确认随译出现在系统托盘，且不弹出设置窗口。
2. 在 Windows 启动应用中停用随译，重新进入常规页，确认状态显示为停用。可在常规页重新开启或移除启动项。关闭后重新登录，确认随译没有自行启动。带便携标记的版本应显示开关不可用。
3. 启用目标应用的沉浸模式自动重启，直接打开它。确认正常退出时会重开进入沉浸模式，拒绝退出或最小化到托盘时保留进程，由用户决定是否手动重启。

### 单实例手动验收（Windows）

1. 随译未运行时，快速连续启动多个副本。等待几秒后应只剩一个随译主进程和一份托盘图标。
2. 关闭设置窗口，使软件只在托盘常驻。记下主进程的 PID，再次运行同一个程序，并从另一目录启动便携副本。应只剩原 PID，且托盘仍只有一份。
3. 从托盘退出随译，确认主进程已结束。再次启动应生成新 PID，并可从托盘打开设置。结束测试主进程后重复启动，确认异常终止也不会阻止重开。

### 框内鼠标操作手动验收（Windows）

1. 使用没有 `frame_click_through` 的旧配置打开两个翻译框，确认两者都默认穿透。在 A 框的悬停工具条切到框内拖动，检查指针和手形图标、切换提示及自动消失的状态消息。B 框应仍可穿透，配置文件的内容和修改时间应保持原样。
2. 在 A 框正文拖动，再移到各边和角落缩放。切回穿透后重复边角缩放，并用工具条手柄移动。点击工具条按钮只执行该按钮的操作。两种模式下分别打开原文和暂停，再切换鼠标操作，原文/译文和暂停/继续状态应保持，工具条仍可操作。
3. 在可滚动的下方应用上分别测试框内正文、边缘和工具条。穿透正文时，滚轮应驱动下方应用，译文随之滚动。框内拖动时，框接收的滚轮不应滚动下方应用或让译文产生假位移。穿透模式下，滚轮落在由框接收的边缘或工具条上也不应造成假位移。
4. 把翻译框缩窄。工具条优先保留手柄、模式切换和关闭，显示出来的按钮都可点击。在不同缩放比例的显示器上各测一次（如 100% 和 150%），再跨屏移动翻译框，确认正文、边角和工具条的鼠标命中位置与画面一致。
5. 在浅色和深色背景上切换模式。边框颜色、线宽、圆角保持一致，仅框内玻璃高光淡入淡出，正文仍清晰。关闭系统动画后按减少动态效果的设置切换。
6. 在设置页把「框内鼠标操作」改为「框内拖动」。已打开的框保持原模式，新框立即采用拖动。重开设置窗口再重启应用，确认设置仍为拖动，新框仍采用该值。切换简体中文和英文，核对设置行、工具条提示与状态消息。
7. 保持两种鼠标模式的框同时打开，在「翻译框圆角」输入 0–128 的整数。所有已打开的框（包括暂停的框）应实时预览，模式和译文保留。输入超出范围时立即改为最近的边界值，回车或失焦后保存。清空输入框或输入范围内的小数后提交，会恢复已保存的值。
8. 保存圆角后，用框选快捷键拖出选区。拖动中的选区与松手后生成的翻译框都采用相同的圆角设置。保存 0 再框选，选区和翻译框均使用直角。
